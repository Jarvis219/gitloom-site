*Uncommitted changes* の行を選び、コミットしたいものをステージして（[行単位のステージ](/ja/docs/staging-single-lines/)を参照）、メッセージを書いて <kbd>⌘↩</kbd> を押します。

## コミットフォーム

- *修正* は新しいコミットを作る代わりに直前のコミットを変更します。チェックを入れている間は、そのコミットがすでに変更しているファイルも一覧に表示されます。
- *共同作成者* は、以前に追加した共同作成者を含め、最近の履歴に登場する人を候補として表示します。
- コミットの実行中は、フックの出力（`pre-commit` のリンターやテストなど）がメッセージの下に表示されます。1 分経ってもフックが実行中の場合は、GitLoom がそれを知らせ、*停止* を提案します。
- 1 行で、誰の名義でコミットするかが表示されます。メールがリポジトリの[プロファイル](/ja/docs/profiles/)と一致しない場合や、GitHub アカウントのメールのどれでもない場合（GitHub がコミットをあなたに関連付けられない場合）は警告が出ます。

AI をオンにしていれば、<kbd>⌥⌘G</kbd> でメッセージを書いてもらえます（[プロバイダの選び方](/ja/docs/choosing-a-provider/)を参照）。

## メッセージの設定

**設定 ▸ Git ▸ コミットメッセージ** では、フォームの初期内容となるテンプレートと、カウンタが黄色と赤に変わる要約の長さ（デフォルトは 50 文字と 72 文字）を設定できます。警告するだけで、切り詰められることはありません。リポジトリ自身の `commit.template` がある場合はそちらが優先されます。

## git に表示されないファイル

- すでに追跡されているファイルを*無視* すると、GitLoom は*追跡を停止*（`git rm --cached`）を提案します。ファイルは次のコミットでリポジトリから外れ、ディスクには残ります。
- ローカル設定のように意図的に変更する追跡済みファイルは、変更されたファイルを右クリック ▸ *ローカルの変更を隠す* を選びます。ファイル一覧の上の行に隠しているファイルの数が表示され、*表示…* で元に戻せます。
- Mac のディスクでは、Finder で `readme.md` を `README.md` に名前変更しても git には見えません。GitLoom はこれを検出し、*名前変更を記録* を提案します。

## コミットを取り消す

<kbd>⌘Z</kbd> で直前のコミットや修正を取り消せます。[取り消しとやり直し](/ja/docs/undo-and-redo/)を参照してください。
