バグの報告や機能のリクエストは [GitHub Issues](https://github.com/Jarvis219/gitloom-site/issues) で行ってください。

## 含める情報

- GitLoom のバージョン（**GitLoom ▸ GitLoom について**、または **設定 ▸ 一般 ▸ アップデート**）と macOS のバージョン。
- 問題が起きるまでの手順。
- 期待した結果と、実際に起きたこと。
- 問題がわかるならスクリーンショット。

git が行ったことに関する問題なら、**ウインドウ ▸ Git ログ** のコマンドが役に立ちます（[トラブルシューティング](/ja/docs/troubleshooting/)を参照）。さらに詳しく調べるには、**設定 ▸ 詳細** の*デバッグログを書き出す* をオンにします。URL に含まれるパスワードとトークンはそこでは隠されます。

> **Caution** Issue は公開されます。トークン、パスワード、SSH 鍵、非公開のコードは絶対に貼り付けないでください。ログやスクリーンショットは添付する前に確認してください。

## クラッシュした後

GitLoom が予期せず終了した場合、次回の起動時に報告するかどうかを尋ねます。選択肢は次のとおりです:

- *GitHub で報告…*: ブラウザで新しい Issue が開き、GitLoom と macOS のバージョン、エラー、クラッシュしたスレッドの先頭部分が入力されています。内容を読み、何をしていたかを書き加えて、自分で送信します。
- *レポートを表示*: macOS が保存したクラッシュレポートを Finder で表示します。
- *後で*。

あなたが自分で Issue を送信しない限り、何も送信されません。この質問を止めるには、*今後は表示しない* にチェックを入れるか、**設定 ▸ 詳細** の*クラッシュの報告を提案する* をオフにします。

**ヘルプ ▸ 問題を報告…** を使えば、いつでもブラウザで空の Issue を開けます。
