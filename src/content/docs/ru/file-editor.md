GitLoom умеет показывать и редактировать файлы вашего репозитория, так что для небольшой правки не нужно другое приложение.

## Как открыть файл

- <kbd>⌘P</kbd> (Быстрое открытие) открывает любой файл репозитория.
- Переключатель «Ссылки/Файлы» на боковой панели показывает дерево файлов. Там же можно выбрать *Новый файл…* или *Новая папка…*, *Переименовать…* или *Переместить в Корзину*, а также *Показать игнорируемые файлы*.

Файл открывается для просмотра. Нажмите <kbd>⌘E</kbd> или *Изменить файл*, чтобы редактировать его. Esc возвращает к графу.

## Клавиши редактора

| Клавиши | Действие |
|---|---|
| <kbd>⌘S</kbd> | Сохранить |
| <kbd>⌥⌘S</kbd> | Сохранить и проиндексировать |
| <kbd>⌘L</kbd> | Перейти к строке |
| <kbd>⌥⌘F</kbd> | Найти и заменить |
| <kbd>⌘/</kbd> | Закомментировать или раскомментировать выбранные строки |
| <kbd>⌘]</kbd> / <kbd>⌘[</kbd> | Увеличить / уменьшить отступ выбранных строк |

Среди параметров редактора — *Переносить строки*, *Показывать пробелы и табуляции*, *Закрывать скобки и кавычки* и *Поле сравнивает с HEAD*. Шрифт кода и его размер задаются в **Настройки ▸ Оформление**.

## Если файл изменился на диске

Если другое приложение меняет файл, пока у вас есть несохранённые правки, GitLoom сообщит об этом и предложит *Оставить мою*, *Перезагрузить* или *Сравнить*. Для файла с маркерами конфликта GitLoom предупреждает, что сохранение не отмечает конфликт как разрешённый; для этого используйте [редактор конфликтов](/ru/docs/resolving-conflicts/).

GitLoom также откладывает установку обновления, пока в файле есть несохранённые изменения.

## Другой редактор

*Открыть во внешнем редакторе* открывает файл в приложении, выбранном в **Настройки ▸ Интеграции ▸ Открывать файлы в**. *Своя команда* там имеет приоритет; в неё подставляются `$FILE`, `$LINE` и `$REPO`, например:

```sh
code -g $FILE:$LINE
```
