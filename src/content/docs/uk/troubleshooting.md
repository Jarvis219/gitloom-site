Більшість проблем у GitLoom можна скасувати або пояснити. Почніть звідси.

## Щось пішло не так у репозиторії

- **Спершу скасуйте**: <kbd>⌘Z</kbd> або **Редагування ▸ Історія операцій…**. Більшість операцій можна скасувати (див. [Скасування й повтор](/uk/docs/undo-and-redo/)).
- **Коміти ніби зникли**: їх знайдуть **Репозиторій ▸ Reflog…** і **Знайти втрачені коміти…** (див. [Відновлення через reflog](/uk/docs/reflog-recovery/)).
- **Застрягли в rebase чи злитті**: репозиторій, залишений посеред такої операції, показує банер із кнопками *Продовжити* й *Перервати* — і після перезапуску GitLoom теж.

## Що зробив GitLoom

**Вікно ▸ Журнал Git** (<kbd>⌥⇧⌘L</kbd>) показує всі команди git, які запускав GitLoom: репозиторій, команду, тривалість і код завершення. Зберігається лише командний рядок, але ніколи — його вивід, ввід чи облікові дані.

Тонка рухома лінія під панеллю інструментів означає, що git обмінюється даними з віддаленим репозиторієм; наведіть на неї вказівник, щоб побачити, з яким. Повідомлення про повільну операцію має кнопку *Скасувати*.

## Поширені проблеми

- **GitLoom не знаходить git або каже, що він застарий.** Установіть git 2.40 або новіший (див. [Встановлення](/uk/docs/install/)) чи виберіть інший git у **Параметри ▸ Git ▸ Виконуваний файл git**.
- **Хук не знаходить node, python чи лінтер.** Додайте потрібні йому папки в *Додатковий PATH* у **Параметри ▸ Git ▸ Хуки**. Це стосується репозиторіїв, відкритих після зміни.
- **Хук зависає.** Коміт, хук якого все ще працює через хвилину, повідомляє про це й пропонує *Зупинити*. *Зупиняти хук через* у **Параметри ▸ Git ▸ Хуки** зупиняє його автоматично (за замовчуванням через 10 хвилин).
- **Використовується не той SSH-ключ.** Налаштуйте [облікові записи SSH](/uk/docs/ssh-accounts/).

## Журнали й кеші

У **Параметри ▸ Додатково**:

- *Записувати журнал налагодження* записує команди git, які запускає GitLoom, з їхнім статусом завершення й часом, у файл у папці журналів. Паролі й токени в URL приховуються. *Показати папку журналів* відкриває її.
- *Очистити кеші…* вилучає pull request і задачі, збережені для роботи офлайн, і кешовані версії файлів. За потреби їх буде отримано знову.
- Якщо файл параметрів не вдається прочитати, GitLoom відкладає його вбік, запускається з типовими параметрами й повідомляє про це тут.

Якщо нічого з цього не допомогло, [повідомте про проблему](/uk/docs/report-an-issue/).
