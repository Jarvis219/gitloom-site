GitLoom може показувати й редагувати файли вашого репозиторію, тож для дрібного виправлення не потрібен інший застосунок.

## Як відкрити файл

- <kbd>⌘P</kbd> (Швидке відкриття) відкриває будь-який файл репозиторію.
- Перемикач «Посилання / Файли» на бічній панелі показує дерево файлів. Там також можна створити *Новий файл…* чи *Нову папку…*, *Перейменувати…* або *Перемістити в Смітник*, а також *Показати ігноровані файли*.

Файл відкривається для перегляду. Натисніть <kbd>⌘E</kbd> або клацніть *Редагувати файл*, щоб редагувати його. Esc повертає до графа.

## Клавіші редагування

| Клавіші | Дія |
|---|---|
| <kbd>⌘S</kbd> | Зберегти |
| <kbd>⌥⌘S</kbd> | Зберегти й проіндексувати |
| <kbd>⌘L</kbd> | Перейти до рядка |
| <kbd>⌥⌘F</kbd> | Знайти й замінити |
| <kbd>⌘/</kbd> | Закоментувати або розкоментувати вибрані рядки |
| <kbd>⌘]</kbd> / <kbd>⌘[</kbd> | Збільшити / зменшити відступ вибраних рядків |

Серед параметрів редактора є *Переносити рядки*, *Показувати пробіли й табуляції*, *Закривати дужки й лапки* та *Поле порівнює з HEAD*. Шрифт коду та його розмір задаються в **Параметри ▸ Вигляд**.

## Коли файл змінюється на диску

Якщо інший застосунок змінює файл, поки у вас є незбережені правки, GitLoom повідомить про це й запропонує *Залишити мою*, *Перезавантажити* або *Порівняти*. Для файлу з маркерами конфлікту буде вказано, що збереження не позначає його розв’язаним; для цього скористайтеся [редактором конфліктів](/uk/docs/resolving-conflicts/).

Також GitLoom чекає з установленням оновлення, поки у файлі є незбережені зміни.

## Інший редактор

*Відкрити в зовнішньому редакторі* відкриває файл у застосунку, вибраному в **Параметри ▸ Інтеграції ▸ Відкривати файли за допомогою**. *Власна команда* там має перевагу над ним; `$FILE`, `$LINE` і `$REPO` підставляються автоматично, наприклад:

```sh
code -g $FILE:$LINE
```
