Коли злиття, rebase, cherry-pick чи pull натрапляє на конфлікт, операція зупиняється, а банер пояснює, що відбувається. Файли з конфліктами перелічено на панелі подробиць.

![Тристоронній редактор конфліктів із вашою стороною, їхньою стороною й результатом](/shots/conflict-light.png)

## Редактор злиття

Відкрийте файл із конфліктом у тристоронньому редакторі злиття: ваша сторона, їхня сторона й результат.

- Беріть одну зі сторін для кожного конфлікту чи для кожного рядка.
- Редагуйте результат безпосередньо.
- <kbd>⌥⌘↑</kbd> і <kbd>⌥⌘↓</kbd> переходять між конфліктами.
- Позначте *Увесь файл*, щоб бачити кожну сторону як цілий файл із конфліктами на місці. Стовпці вирівнюються й прокручуються разом.

Коли файл правильний, натисніть *Зберегти й позначити розв’язаним* (<kbd>⌘S</kbd>).

## Особливі випадки

- Конфлікт через перейменування (перейменовано з обох боків або перейменовано з одного й видалено з іншого) так і позначається.
- Двійковий файл можна переглянути з обох боків, перш ніж вибрати.
- Банер попереджає, коли сторони відрізняються лише закінченнями рядків (CRLF / LF).

## Власний інструмент злиття

Файл можна також відкрити в зовнішньому інструменті злиття. GitLoom використовує `merge.tool` з git або інструмент, вибраний у **Параметри ▸ Інтеграції ▸ Інструмент злиття**.

## Завершення чи зупинка

Коли всі файли розв’язано, натисніть *Продовжити* на банері. *Пропустити* пропускає поточний коміт rebase чи cherry-pick; *Перервати* повертає все як було. Репозиторій, залишений посеред rebase чи злиття, знову показує банер після перезапуску GitLoom.
