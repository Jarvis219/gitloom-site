다른 AI 도구(Claude Code, Claude Desktop, Cursor, VS Code 등)는 GitLoom의 MCP 서버를 통해 저장소를 다룰 수 있습니다. 직접 켜기 전까지는 꺼져 있습니다.

## 켜기

**설정 ▸ 통합 ▸ MCP 서버**에서 *외부 AI 도구 권한*을 다음 중 하나로 설정하세요:

- *아무것도 안 함 (끔)*;
- *읽기: 상태, 기록, diff, blame*;
- *읽기 및 변경: 커밋, 브랜치, 스태시, 풀, 푸시도 가능*.

그런 다음 도구를 연결하세요. Claude Code라면 그곳에 표시된 줄을 복사해 터미널에서 실행하세요. 다음과 같은 형태입니다:

```sh
claude mcp add gitloom -- "/Applications/GitLoom.app/Contents/Helpers/gitloom-mcp"
```

다른 도구라면 그곳에 표시된 JSON을 도구의 MCP 설정에 복사하세요. GitLoom은 다른 도구의 파일을 절대 수정하지 않습니다. `gitloom mcp` 명령으로도 서버를 실행할 수 있습니다([gitloom 명령줄 도구](/ko/docs/the-gitloom-command-line-tool/) 참고).

## 읽기

도구는 열려 있거나 시작 페이지의 최근 목록에 있는 저장소의 상태, 기록, diff, blame, 브랜치, 스태시를 볼 수 있습니다. GitLoom이 실행 중이면 선택한 커밋이나 열린 파일처럼 지금 보고 있는 것을 물어볼 수도 있습니다. 아무것도 변경할 수 없습니다.

## 읽기 및 변경

도구는 GitLoom이 실행 중일 때 탭에 열린 저장소에서 스테이징, 커밋, 브랜치 만들기와 전환, 스태시, 페치, 풀(빨리 감기만), 푸시도 할 수 있습니다. 각 변경은 도구 이름과 *실행 취소* 버튼과 함께 창에 표시되고, 작업 기록에도 남습니다.

*푸시 전에 묻기*를 켜면 푸시가 저장소 창에서 답을 기다리며, 60초가 지나면 거부됩니다.

어떤 도구도 강제 푸시, 재설정, 버리기, 삭제, 기록 다시 쓰기를 할 수 없습니다.

## 풀 리퀘스트, 이슈, CI

*내 계정을 통한 풀 리퀘스트, 이슈, CI*를 켜면 도구가 GitLoom에 연결된 계정을 통해 저장소의 풀 리퀘스트, 이슈, CI 실행을 읽을 수 있습니다. *읽기 및 변경*이면 현재 브랜치에 대한 풀 리퀘스트를 열고 댓글을 달 수도 있습니다. 도구는 토큰을 절대 볼 수 없으며, 아무것도 병합, 승인, 닫기할 수 없습니다.

설정의 *최근 활동*에 가장 최근 호출이 표시됩니다.
