대화형 리베이스는 일련의 커밋을 다시 작성합니다. GitLoom은 계획을 편집 가능한 목록으로 보여 주며, 시작하기 전까지 저장소에는 아무 일도 일어나지 않습니다.

## 편집기 열기

- 커밋을 오른쪽 클릭 ▸ *여기서부터 대화형 리베이스…*.
- 또는 브랜치를 다른 브랜치 위에 놓고 *대화형 리베이스*를 선택합니다.
- 여러 커밋을 선택한 상태에서 *선택한 커밋 대화형 리베이스…* 를 선택하면 그 커밋들이 선택된 채로 편집기가 열립니다.

맨 첫 커밋부터(`--root`)도 가능합니다. 편집기는 그래프 자리에 표시됩니다.

## 계획 편집

각 행은 커밋이며, 가장 오래된 커밋이 맨 위에 있습니다. 메뉴나 키로 동작을 설정하세요:

| 키 | 동작 |
|---|---|
| <kbd>P</kbd> | pick |
| <kbd>R</kbd> | reword |
| <kbd>E</kbd> | edit |
| <kbd>S</kbd> | squash |
| <kbd>F</kbd> | fixup |
| <kbd>C</kbd> | fixup -C |
| <kbd>D</kbd> | drop |

행을 드래그하거나 <kbd>⌥↑</kbd>와 <kbd>⌥↓</kbd>로 순서를 바꿉니다. <kbd>⌘Z</kbd>는 계획의 변경을 실행 취소합니다.

- reword 메시지는 미리 써 둘 수 있으므로 리베이스가 멈추지 않고 진행됩니다.
- 행의 메뉴에 있는 *뒤에 명령 추가…* 로 그 시점에 명령을 실행할 수 있습니다(`exec` 줄. 예를 들어 실패하면 리베이스를 멈추는 테스트).
- 리베이스하는 커밋 위에 쌓인 브랜치도 함께 이동합니다(`--update-refs`). 체크를 해제하면 이동하지 않습니다.
- 범위 안의 병합은 기본적으로 평탄화됩니다. *병합 유지*를 체크하면 유지됩니다(`--rebase-merges`). 이때 계획에는 병합의 각 쪽이 시작하는 위치와 병합이 다시 만들어지는 위치도 표시되며, 커밋은 자기 쪽 안에서만 이동할 수 있습니다.

## 시작 또는 취소

<kbd>⌘↩</kbd>로 시작하고 Esc로 취소합니다. 완료 후에는 리베이스 전체가 한 번의 실행 취소 단위가 됩니다.

## 더 빠른 편집

편집기를 열지 않고도:

- 인접한 여러 커밋 선택 ▸ *커밋 N개 스쿼시*(메시지를 오래된 순으로 합쳐 바로 실행. 메시지를 직접 쓰려면 *커밋 N개 스쿼시 후 메시지 편집…*) 또는 *커밋 N개 삭제…*;
- 커밋을 오른쪽 클릭 ▸ *메시지 편집…*, *커밋 삭제…*, *위로 이동/아래로 이동*.
