GitLoom에서 생기는 문제는 대부분 실행 취소하거나 원인을 확인할 수 있습니다. 여기서 시작하세요.

## 저장소에서 문제가 생겼을 때

- **먼저 실행 취소**: <kbd>⌘Z</kbd> 또는 **편집 ▸ 작업 기록…**. 대부분의 작업은 실행 취소할 수 있습니다([실행 취소와 다시 실행](/ko/docs/undo-and-redo/) 참고).
- **커밋이 사라진 것 같을 때**: **저장소 ▸ Reflog…** 와 **잃어버린 커밋 찾기…** 로 찾을 수 있습니다([Reflog 복구](/ko/docs/reflog-recovery/) 참고).
- **리베이스나 병합 도중에 멈췄을 때**: 도중에 남겨진 저장소에는 *계속*과 *중단*이 있는 배너가 표시되며, GitLoom을 다시 시작한 뒤에도 마찬가지입니다.

## GitLoom이 한 일 보기

**윈도우 ▸ Git 로그**(<kbd>⌥⇧⌘L</kbd>)는 GitLoom이 실행한 모든 git 명령을 나열합니다: 저장소, 명령, 걸린 시간, 종료 코드. 명령줄만 보관하며, 출력, 입력, 자격 증명은 절대 보관하지 않습니다.

도구 막대 아래에서 움직이는 얇은 선은 git이 원격과 통신 중이라는 뜻입니다. 포인터를 올리면 무엇인지 볼 수 있습니다. 느린 작업의 메시지에는 *취소*가 있습니다.

## 흔한 문제

- **GitLoom이 git을 찾지 못하거나 너무 오래되었다고 합니다.** git 2.40 이상을 설치하거나([설치](/ko/docs/install/) 참고), **설정 ▸ Git ▸ Git 바이너리**에서 다른 git을 선택하세요.
- **훅이 node, python, 린터를 찾지 못합니다.** 필요한 폴더를 **설정 ▸ Git ▸ 훅**의 *추가 PATH*에 추가하세요. 이후에 연 저장소에 적용됩니다.
- **훅이 멈춰 있습니다.** 1분이 지나도 훅이 실행 중인 커밋은 그렇다고 알리고 *중지*를 제안합니다. **설정 ▸ Git ▸ 훅**의 *훅 중지 시간*을 설정하면 자동으로 중지합니다(기본값 10분 후).
- **잘못된 SSH 키가 사용됩니다.** [SSH 계정](/ko/docs/ssh-accounts/)을 설정하세요.

## 로그와 캐시

**설정 ▸ 고급**에서:

- *디버그 로그 기록*은 GitLoom이 실행하는 git 명령을 종료 상태, 시간과 함께 로그 폴더의 파일에 기록합니다. URL의 암호와 토큰은 숨겨집니다. *로그 폴더 보기*로 폴더를 엽니다.
- *캐시 지우기…* 는 오프라인용으로 보관한 풀 리퀘스트와 이슈, 캐시된 파일 버전을 제거합니다. 필요할 때 다시 가져옵니다.
- 설정 파일을 읽을 수 없으면 GitLoom은 그 파일을 옆으로 옮기고 기본값으로 시작하며, 여기에 그렇게 표시합니다.

그래도 해결되지 않으면 [문제를 신고](/ko/docs/report-an-issue/)하세요.
