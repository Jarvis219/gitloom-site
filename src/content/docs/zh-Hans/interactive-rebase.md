交互式变基会改写一系列提交。GitLoom 将计划显示为一个可编辑的列表；在你开始之前，仓库不会有任何变化。

## 打开编辑器

- 右键点按一个提交 ▸ *从此处开始交互式变基…*。
- 或者把一个分支拖放到另一个分支上，然后选择*交互式变基*。
- 选中多个提交时，*交互式变基所选提交…* 会打开编辑器并选中这些提交。

它也能从第一个提交开始（`--root`）。编辑器会取代提交图。

## 编辑计划

每一行是一个提交，最早的在最上面。从菜单或用按键设置它的动作：

| 按键 | 动作 |
|---|---|
| <kbd>P</kbd> | pick |
| <kbd>R</kbd> | reword |
| <kbd>E</kbd> | edit |
| <kbd>S</kbd> | squash |
| <kbd>F</kbd> | fixup |
| <kbd>C</kbd> | fixup -C |
| <kbd>D</kbd> | drop |

拖动行，或使用 <kbd>⌥↑</kbd> 和 <kbd>⌥↓</kbd> 来重新排序。<kbd>⌘Z</kbd> 撤销对计划的更改。

- reword 的信息可以预先写好，这样变基运行时不会中途停下。
- 行菜单中有*在后面添加命令…*，可在该位置运行一个命令（一行 `exec`，例如失败时会让变基停下的测试）。
- 叠在被变基提交之上的分支会随之移动（`--update-refs`），除非你取消勾选。
- 范围内的合并默认会被拉平。勾选*保留合并*即可保留它们（`--rebase-merges`）。这时计划还会显示合并每一侧的起点以及合并重新生成的位置，提交只能在自己那一侧内移动。

## 开始或取消

<kbd>⌘↩</kbd> 开始，Esc 取消。完成后，整个变基算作一步撤销。

## 更快的编辑

不打开编辑器也可以：

- 选中多个相邻提交 ▸ *压缩 N 个提交*（立即运行，信息按从旧到新合并；选*…并编辑信息*可自己撰写）或*删除 N 个提交…*；
- 右键点按一个提交 ▸ *编辑信息…*、*删除提交…*、*上移/下移*。
